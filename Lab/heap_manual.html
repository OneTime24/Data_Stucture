Heap: The Biggest One Is Always on Top

Data Structures Lab Manual
Instructor: Hamza Raziq Khan Language: C++ Before this lab: Arrays, Binary Trees, Classes

1.The Problem: “Give Me the Biggest, Again and Again”

Many programs ask the same question again and again: what is the biggest value right now?

  • A game shows the top score on the leaderboard.
  • A hospital treats the most urgent patient first.
  • A computer runs the most important task first.

With a normal array, every question is slow. To find the biggest value, you must look at every element. That is O(n) work, every single time. New values also keep coming, so you cannot just sort once and relax.

We need a structure with three fast powers:

1
See the biggest in one step.
2
Remove the biggest fast, and the next biggest is ready.
3
Add a new value fast, without breaking anything.

That structure is the heap.

2.The Heap Idea

Real life

Think of a hospital emergency room. Patients do not get treated in the order they arrived. The most urgent patient goes first. When a new patient arrives, the staff check the urgency. The new patient moves forward, past less urgent patients, and stops at the right place. Nobody sorts the whole room again. Only one person moves.

A heap is a binary tree with two rules. Both rules must always be true.

Rule 1: Shape rule. The tree is complete. Every level is full, except maybe the last level. The last level fills from the left, with no gaps.

Rule 2: Heap property. In a max-heap, every parent is greater than or equal to its children. So the biggest value is always at the root, on top.

A min-heap is the same idea, flipped. Every parent is smaller than or equal to its children, and the smallest value sits at the root. This whole manual uses a max-heap. The min-heap is your lab task later.

Big warning

A heap is not a sorted list. It is also not a BST. In a heap, a left child can be bigger or smaller than the right child. We do not care. We only care about one thing: parent versus its own children. Only the root is guaranteed to be the maximum.

A heap is like a good manager. It does not know where everyone is. It only knows who is on top. 💼

3.A Tree That Lives Inside an Array

Here is the beautiful trick. A complete binary tree fits into an array with no gaps. We store the nodes level by level, left to right. No pointers. No node objects. Just one array.

The same heap as an array: [ 40, 25, 30, 10, 15, 20 ]. Read the tree level by level.

Because the tree has no gaps, we can find the family of any node with simple math. For a node at index i (counting from 0):

parent(i) = (i − 1) / 2   |   leftChild(i) = 2i + 1   |   rightChild(i) = 2i + 2

Check index 4 (value 15). Its parent is index (4−1)/2 = 1, value 25. Correct. The children of index 1 are 2(1)+1 = 3 and 2(1)+2 = 4, values 10 and 15. Correct.

Why this matters

Moving up or down the tree is just one formula. No searching. No pointers. That is why heap operations are fast: the tree is complete, so its height is only about log2(n). For 1,000,000 values, the height is only about 20.

4.Insert: Add at the End, Then Bubble Up

Insert has two steps. First, put the new value at the end of the array. The shape rule stays happy, because the last level fills from the left. But the heap property may be broken: the new value may be bigger than its parent.

So step two: bubble up. Compare the new value with its parent. If it is bigger, swap them. Repeat. Stop when the parent is bigger, or when the value reaches the root. Only one value travels. The rest of the tree does not move.

Worked example. Insert 20, 15, 30, 10, 25, 40, one by one. Watch the bold value travel.

InsertWhat happensArray after
20First value. It becomes the root.[ 20 ]
1515 is smaller than parent 20. It stays.[ 20, 15 ]
3030 is bigger than parent 20. Swap. 30 is the new root.[ 30, 15, 20 ]
1010 is smaller than parent 15. It stays.[ 30, 15, 20, 10 ]
2525 is bigger than parent 15. Swap. Parent now 30, bigger. Stop.[ 30, 25, 20, 10, 15 ]
4040 beats parent 20, swap. 40 beats new parent 30, swap. 40 is the root.[ 40, 25, 30, 10, 15, 20 ]

Cost: the value travels up at most the height of the tree. So insert is O(log n).

5.Peek and Extract Max: Take the Root, Then Sink Down

Peek is trivial. The maximum is at index 0. Read it. Done. O(1).

Extract max removes the root. This makes a hole at the top. We fix it in three steps:

1
Save the root value. That is the answer.
2
Move the last value in the array to the root. Delete the last place. The shape rule stays happy.
3
Sink down (heapify down): compare the new root with its children. Swap it with the bigger child. Repeat until both children are smaller, or it reaches a leaf.

Worked example. Extract max from [ 40, 25, 30, 10, 15, 20 ].

  • Answer is 40. Move the last value, 20, to the root: [ 20, 25, 30, 10, 15 ].
  • Children of 20 are 25 and 30. The bigger child is 30. Swap: [ 30, 25, 20, 10, 15 ].
  • Index of 20 is now 2. Its children would be index 5 and 6. They do not exist. Stop.
  • Final heap: [ 30, 25, 20, 10, 15 ]. New maximum is 30. Correct.
Why the bigger child?

When a value sinks, it must swap with the bigger child. The bigger child moves up, and a parent must be bigger than both children. If you swap with the smaller child, the bigger child stays below its new, smaller parent. Rule broken.

Cost: the value sinks at most the height of the tree. So extract max is also O(log n).

7.Build a Heap Fast, and Heap Sort

You can build a heap by inserting n values one by one: O(n log n). But there is a faster way, called heapify.

The idea: leaves are already perfect mini-heaps of size 1. So start at the last parent, index n/2 − 1, and sink each value down, going backwards up to the root. Most nodes are near the leaves, so most sinks are very short. Total cost: O(n).

Worked example. Build a heap from [ 5, 3, 8, 1, 9, 2 ]. Last parent is index 2 (value 8).

  • Index 2, value 8: child is index 5, value 2. 8 is bigger. No swap.
  • Index 1, value 3: children are 1 and 9. Swap 3 with 9: [ 5, 9, 8, 1, 3, 2 ].
  • Index 0, value 5: children are 9 and 8. Swap 5 with 9: [ 9, 5, 8, 1, 3, 2 ]. Now 5 sits at index 1; its children are 1 and 3, both smaller. Stop.
  • Result: [ 9, 5, 8, 1, 3, 2 ]. A valid max-heap.

Heap sort is now easy to see. Build a max-heap. Take the max (the root), and put it at the end of the array, where it belongs in sorted order. Shrink the heap by one. Sink the new root down. Repeat. At the end, the array is sorted, smallest to biggest.

Sorting [ 5, 3, 8, 1, 9, 2 ] with heap sort gives [ 1, 2, 3, 5, 8, 9 ]. Total cost O(n log n), and it needs no extra array. The sort happens inside the same array.

Priority queue

A heap is the standard way to build a priority queue: a queue where the most important item leaves first, not the oldest item. C++ even has one ready-made: std::priority_queue. In this lab you build your own, so you know what is inside the black box.

8.The Full C++ Code

Read it top to bottom. Every part of this code was used in the examples above, and the output below is the real output of this exact code.

// Heap Lab - Max Heap in C++
// FAST NUCES Peshawar - Data Structures Lab
// Instructor: Hamza Raziq Khan
#include <iostream>
#include <vector>
using namespace std;

class MaxHeap {
private:
    vector<int> heap;   // the tree lives inside this array

    int parent(int i)     { return (i - 1) / 2; }
    int leftChild(int i)  { return 2 * i + 1; }
    int rightChild(int i) { return 2 * i + 2; }

    // Move the value at index i UP until the heap rule is fine again.
    void heapifyUp(int i) {
        while (i > 0 && heap[i] > heap[parent(i)]) {
            swap(heap[i], heap[parent(i)]);
            i = parent(i);
        }
    }

    // Move the value at index i DOWN until the heap rule is fine again.
    void heapifyDown(int i) {
        int n = heap.size();
        while (true) {
            int largest = i;
            int l = leftChild(i);
            int r = rightChild(i);
            if (l < n && heap[l] > heap[largest]) largest = l;
            if (r < n && heap[r] > heap[largest]) largest = r;
            if (largest == i) break;          // rule is fine, stop
            swap(heap[i], heap[largest]);
            i = largest;
        }
    }

public:
    bool isEmpty() { return heap.size() == 0; }

    // Step 1: put the new value at the end. Step 2: bubble it up.
    void insert(int value) {
        heap.push_back(value);
        heapifyUp(heap.size() - 1);
    }

    // See the biggest value. Do not remove it.
    int peek() {
        if (isEmpty()) return -1;
        return heap[0];
    }

    // Remove and return the biggest value (always at index 0).
    int extractMax() {
        if (isEmpty()) return -1;
        int maxValue = heap[0];
        heap[0] = heap.back();   // move the last value to the top
        heap.pop_back();         // remove the last place
        if (!isEmpty()) heapifyDown(0);   // sink the new root down
        return maxValue;
    }

    void printArray() {
        for (int x : heap) cout << x << " ";
        cout << endl;
    }
};

// Turn any array into a heap, in place. Start from the last parent
// and heapify down, one by one, up to the root.
void buildHeap(vector<int> &a) {
    int n = a.size();
    for (int i = n / 2 - 1; i >= 0; i--) {
        int j = i;
        while (true) {
            int largest = j;
            int l = 2 * j + 1, r = 2 * j + 2;
            if (l < n && a[l] > a[largest]) largest = l;
            if (r < n && a[r] > a[largest]) largest = r;
            if (largest == j) break;
            swap(a[j], a[largest]);
            j = largest;
        }
    }
}

// Heap sort: build a heap, then keep taking the max to the end.
void heapSort(vector<int> &a) {
    buildHeap(a);
    for (int end = (int)a.size() - 1; end > 0; end--) {
        swap(a[0], a[end]);                 // max goes to its final place
        // heapify down inside the smaller part a[0..end-1]
        int j = 0;
        while (true) {
            int largest = j;
            int l = 2 * j + 1, r = 2 * j + 2;
            if (l < end && a[l] > a[largest]) largest = l;
            if (r < end && a[r] > a[largest]) largest = r;
            if (largest == j) break;
            swap(a[j], a[largest]);
            j = largest;
        }
    }
}

int main() {
    MaxHeap h;
    int values[] = {20, 15, 30, 10, 25, 40};
    for (int v : values) {
        h.insert(v);
        cout << "After insert " << v << ": ";
        h.printArray();
    }
    cout << "Peek (max, still inside): " << h.peek() << endl;
    cout << "Extract max: " << h.extractMax() << endl;
    cout << "Heap now: ";
    h.printArray();

    cout << "\nExtract all, one by one: ";
    MaxHeap h2;
    for (int v : values) h2.insert(v);
    while (!h2.isEmpty()) cout << h2.extractMax() << " ";
    cout << endl;

    vector<int> a = {5, 3, 8, 1, 9, 2};
    buildHeap(a);
    cout << "\nbuildHeap on 5 3 8 1 9 2 gives: ";
    for (int x : a) cout << x << " ";
    cout << endl;

    vector<int> b = {5, 3, 8, 1, 9, 2};
    heapSort(b);
    cout << "heapSort on 5 3 8 1 9 2 gives: ";
    for (int x : b) cout << x << " ";
    cout << endl;
    return 0;
}

9.Cost and Common Mistakes

OperationCostWhy
Peek (see the max)O(1)It is always at index 0.
InsertO(log n)One value bubbles up at most the tree height.
Extract maxO(log n)One value sinks down at most the tree height.
Build heap (heapify)O(n)Most nodes are near the leaves, so most sinks are tiny.
Heap sortO(n log n)n extracts, each O(log n). No extra array.
Mistakes students make every year
  • “The heap is sorted.” No. Only the root is the maximum. [ 40, 25, 30 ] is a fine heap and it is not sorted.
  • Mixing two index systems. This manual counts from 0: children are 2i+1 and 2i+2. Some books count from 1: children are 2i and 2i+1. Pick one system and never mix them.
  • Sinking to the smaller child. In a max-heap, always swap with the bigger child.
  • Forgetting to sink after extract. Moving the last value to the root is only half the job. Without heapify down, the root is often small and the heap is broken.
  • Leaving a gap. Insert always goes at the very end, and extract always takes the very last value away. That is what keeps the tree complete.

Dry Run 1. Insert 50, 30, 40, 10 into an empty max-heap, in this order. Write the array after each insert. Draw the final tree.

After 50: [ 50 ]. After 30: [ 50, 30 ]. After 40: [ 50, 30, 40 ] (40 is smaller than 50, it stays as the right child). After 10: [ 50, 30, 40, 10 ]. No value ever bubbles up here, because each new value is smaller than its parent. Final tree: root 50, children 30 and 40, and 10 under 30.

Dry Run 2. A max-heap is stored as [ 90, 70, 80, 40, 60, 75 ]. Do ONE extract max. Write every step and the final array.

Answer is 90. Move the last value, 75, to the root: [ 75, 70, 80, 40, 60 ]. Sink: children of 75 are 70 and 80, swap with the bigger child 80: [ 80, 70, 75, 40, 60 ]. Value 75 is now at index 2; its children (index 5 and 6) do not exist. Stop. Final array: [ 80, 70, 75, 40, 60 ].

Dry Run 3. Is [ 10, 30, 20, 40 ] a valid max-heap? If not, find the FIRST index (smallest index) where the rule breaks, and name the parent and child values.

No, it is not a valid max-heap. Index 1 holds 30. Its parent is index 0, value 10. A child (30) is bigger than its parent (10). That is the first break. (Index 3 also breaks the rule with its parent at index 1, but index 1 is the first one.)

One-Page Summary (Learn This)

  • Heap = complete binary tree + heap property. Max-heap: parent ≥ children. Root = maximum.
  • Index math (from 0): parent = (i−1)/2, left = 2i+1, right = 2i+2.
  • Insert: add at the end, bubble up. Extract: root out, last value to root, sink down. Both O(log n).
  • Peek is O(1). Build heap is O(n). Heap sort is O(n log n) with no extra array.
  • A heap is not sorted, and it is not a BST.
