01 · START HEREThe rule behind everything

A tree that keeps itself searchable

Imagine organizing numbered books on branching shelves. At every shelf, smaller numbers go left and larger numbers go right. That rule often lets you skip large parts of the tree. A balanced BST searches quickly, while a badly stretched tree may still inspect every node.

In plain words: a Binary Search Tree (BST) is a linked structure where each node stores one value and points to at most two children.
all values on the left<NODE < all values on the right

What you will be able to do

  • Explain the BST ordering rule using a real tree.
  • Build nodes with pointers in C++.
  • Insert and search step by step.
  • Run inorder, preorder, and postorder traversals.
  • Delete leaves, one-child nodes, and two-child nodes.
  • Reason about average and worst-case time.
Small warning, big difference: a binary tree allows up to two children. A binary search tree also obeys the ordering rule. Every BST is a binary tree; not every binary tree is a BST. Like every square is a rectangle—but rectangles refuse to all be squares.
02 · ANATOMYLearn the family vocabulary

Meet the tree family

Start at the top. The first node is the root. A node connected below another is its child. A node with no children is a leaf. A smaller tree hanging from any node is a subtree.

Read this tree from the rootnodeleft = smaller · right = larger

The C++ building block

Each node needs three pieces: its value, a pointer to the left child, and a pointer to the right child. A new node begins with no children, so both pointers are nullptr.

bst_node.cpp
struct Node {
    int data;       // The value stored in this node
    Node* left;     // Address of the smaller child
    Node* right;    // Address of the larger child

    Node(int value) {
        data = value;
        left = nullptr;
        right = nullptr;
    }
};

04 · INSERTFind the empty chair

Insertion is a chain of comparisons

A new value does not push other nodes around. It walks down the tree, choosing left or right at each node, until it finds an empty pointer.

Insert 65 into the starter tree

01

65 is larger, so move right.

02
Compare 65 with 70.

65 is smaller, so move left.

03
Compare 65 with 60.

65 is larger, so move right.

04
The right pointer is empty.

Create the new node there. No shuffling, no drama.

Why recursion fits

At every node, insertion asks the same smaller question: “insert this value into the left subtree” or “insert it into the right subtree.” That repeated shape is exactly what recursion handles well.

recursive insert
Node* insert(Node* root, int value) {
    // Empty spot found: create and return a new node.
    if (root == nullptr) {
        return new Node(value);
    }

    if (value < root->data) {
        root->left = insert(root->left, value);
    } else if (value > root->data) {
        root->right = insert(root->right, value);
    } else {
        cout << "Duplicate ignored.\n";
    }

    return root; // Keep the subtree connected to its parent.
}
Why return root? When recursion creates or updates a subtree, the parent must receive its pointer back. Without that return-and-assign pattern, a new node can be created but never connected—an expensive little orphan in memory.
05 · SEARCHDiscard half a direction

Search follows the ordering rule

To find 60, start at 50. Since 60 is larger, the entire left subtree can be ignored. At 70, 60 is smaller, so ignore the right subtree. The next node is 60: found.

BST search

Uses the rule to choose one path. In a balanced tree, it checks only a few nodes.

Ordinary binary tree search

Has no ordering promise. It may need to visit every node.

iterative search
bool search(Node* root, int target) {
    Node* current = root;

    while (current != nullptr) {
        if (target == current->data) {
            return true; // Target found.
        }

        // Choose exactly one direction.
        if (target < current->data)
            current = current->left;
        else
            current = current->right;
    }

    return false; // Reached an empty pointer.
}
Quick check: searching for 35 starts at 50. Where do we go first?
06 · TRAVERSEThree ways to visit everyone

Traversal changes the visiting order

A traversal visits every node exactly once. The three depth-first traversals use the same ingredients—left subtree, node, right subtree—but arrange them differently.

Inorder

Left → Node → Right

20 30 40 50 60 70 80

In a BST, this produces sorted order.

Preorder

Node → Left → Right

50 30 20 40 70 60 80

Useful for copying or saving tree structure.

Postorder

Left → Right → Node

20 40 30 60 80 70 50

Useful when deleting an entire tree.

three recursive traversals
void inorder(Node* root) {
    if (root == nullptr) return;
    inorder(root->left);            // Left
    cout << root->data << " ";    // Node
    inorder(root->right);           // Right
}

void preorder(Node* root) {
    if (root == nullptr) return;
    cout << root->data << " ";    // Node
    preorder(root->left);           // Left
    preorder(root->right);          // Right
}

void postorder(Node* root) {
    if (root == nullptr) return;
    postorder(root->left);          // Left
    postorder(root->right);         // Right
    cout << root->data << " ";    // Node
}
Memory trick: the name tells you when the node is processed. PREorder processes it before its subtrees. INorder processes it in between. POSTorder processes it after.
07 · DELETEThe part everyone side-eyes

Deletion has exactly three cases

First search for the node. Then look only at how many children it has. That number—zero, one, or two—decides the repair.

Case 1: delete a leaf

A leaf has no children. Disconnect it from its parent and free its memory. Deleting 20 from the starter tree needs no rearrangement.

parent → 20becomesparent → nullptr

Case 2: delete a node with one child

Let the child take the deleted node’s place. The parent now points directly to that child—like skipping a person in a phone chain without losing everyone below them.

parent → node → childbecomesparent → child

Case 3: delete a node with two children

We cannot simply remove it because two subtrees would be left homeless. Replace its value with the smallest value in its right subtree—the inorder successor—then delete that duplicate from the right subtree.

find successor→copy value→delete duplicate

Example: delete 50

50 has two children. The smallest value in its right subtree is 60. Copy 60 into the root, then delete the original 60 node. The ordering rule remains valid.

minimum + deletion
Node* findMin(Node* root) {
    // The smallest value is the leftmost node.
    while (root != nullptr && root->left != nullptr) {
        root = root->left;
    }
    return root;
}

Node* remove(Node* root, int value) {
    if (root == nullptr) return nullptr;

    if (value < root->data) {
        root->left = remove(root->left, value);
    } else if (value > root->data) {
        root->right = remove(root->right, value);
    } else {
        // Found the node.
        if (root->left == nullptr) {
            Node* child = root->right;
            delete root;
            return child;
        }
        if (root->right == nullptr) {
            Node* child = root->left;
            delete root;
            return child;
        }

        // Two children: use the inorder successor.
        Node* successor = findMin(root->right);
        root->data = successor->data;
        root->right = remove(root->right, successor->data);
    }
    return root;
}
08 · COMPLEXITYShape decides speed

Fast when short, slow when stretched

A balanced-looking tree has a small height, so operations follow a short path. If values are inserted in sorted order—10, 20, 30, 40, 50—the BST bends into a linked list. The data is still correct, but the speed advantage disappears.

Healthy shape

Each level roughly doubles capacity. Height is about log₂(n).

Average: O(log n)

Skewed shape

Every node has one child. Height becomes n − 1.

Worst case: O(n)
OperationAverageWorstWhy?
SearchO(log n)O(n)Follows one root-to-leaf path
InsertO(log n)O(n)Searches for one empty pointer
DeleteO(log n)O(n)Search plus a local repair
TraversalO(n)O(n)Must visit every node
Important: a plain BST does not balance itself. AVL trees and Red-Black trees add rules that keep height under control. Those are the bouncers who stop the tree from turning into a suspiciously long queue.
09 · BUILDA complete runnable program

Put every operation together

Copy this into one .cpp file. It inserts values, prints three traversals, searches, deletes, prints the height, and frees all allocated memory.

complete_bst.cpp
#include <iostream>
#include <algorithm>
using namespace std;

struct Node {
    int data;
    Node* left;
    Node* right;

    Node(int value) : data(value), left(nullptr), right(nullptr) {}
};

Node* insert(Node* root, int value) {
    if (root == nullptr) return new Node(value);
    if (value < root->data)
        root->left = insert(root->left, value);
    else if (value > root->data)
        root->right = insert(root->right, value);
    return root;
}

bool search(Node* root, int target) {
    while (root != nullptr) {
        if (target == root->data) return true;
        root = (target < root->data) ? root->left : root->right;
    }
    return false;
}

void inorder(Node* root) {
    if (!root) return;
    inorder(root->left);
    cout << root->data << " ";
    inorder(root->right);
}

void preorder(Node* root) {
    if (!root) return;
    cout << root->data << " ";
    preorder(root->left);
    preorder(root->right);
}

void postorder(Node* root) {
    if (!root) return;
    postorder(root->left);
    postorder(root->right);
    cout << root->data << " ";
}

Node* findMin(Node* root) {
    while (root && root->left) root = root->left;
    return root;
}

Node* remove(Node* root, int value) {
    if (!root) return nullptr;

    if (value < root->data)
        root->left = remove(root->left, value);
    else if (value > root->data)
        root->right = remove(root->right, value);
    else {
        if (!root->left) {
            Node* child = root->right;
            delete root;
            return child;
        }
        if (!root->right) {
            Node* child = root->left;
            delete root;
            return child;
        }

        Node* successor = findMin(root->right);
        root->data = successor->data;
        root->right = remove(root->right, successor->data);
    }
    return root;
}

int height(Node* root) {
    if (!root) return -1; // Height in edges
    return 1 + max(height(root->left), height(root->right));
}

void clearTree(Node* root) {
    if (!root) return;
    clearTree(root->left);
    clearTree(root->right);
    delete root;
}

int main() {
    Node* root = nullptr;
    int values[] = {50, 30, 70, 20, 40, 60, 80};

    for (int value : values)
        root = insert(root, value);

    cout << "Inorder: ";
    inorder(root);        // 20 30 40 50 60 70 80
    cout << "\nPreorder: ";
    preorder(root);       // 50 30 20 40 70 60 80
    cout << "\nPostorder: ";
    postorder(root);      // 20 40 30 60 80 70 50

    cout << "\nSearch 60: " << (search(root, 60) ? "Found" : "Not found");
    cout << "\nHeight: " << height(root) << "\n";

    root = remove(root, 20); // Leaf
    root = remove(root, 30); // One child after 20 is gone
    root = remove(root, 50); // Two children

    cout << "After deletions: ";
    inorder(root);
    cout << "\n";

    clearTree(root);      // Prevent memory leaks.
    root = nullptr;
    return 0;
}

Expected output

terminal

Preorder: 50 30 20 40 70 60 80

Search 60: Found
Height: 2
After deletions: 40 60 70 80

Debugging checklist

  • New nodes disappear: assign the recursive result back: root->left = insert(...).
  • Traversal never ends: check that every function stops when root == nullptr.
  • Deletion crashes: store the child pointer before deleting the current node.
  • Memory leaks: call clearTree before the program ends.
  • Duplicate behavior is confusing: choose and document a policy. This manual ignores duplicates.
